# AcxiomCRM

AcxiomCRM is a sample ASP.NET Core MVC CRM application built for managing customers, leads, opportunities, follow-ups, and audits. It uses ASP.NET Core Identity for authentication, Entity Framework Core for persistence, and SQL Server for the database.

## Features
- User registration, login, logout, and role-based access
- Admin, Manager, and SalesExecutive roles
- Customer, lead, opportunity, and follow-up management
- Dashboard with KPI summaries and Chart.js visualizations
- Search, filtering, and validation on list screens
- Audit logging for important record activity
- REST API endpoints for customer, lead, and opportunity data

## Tech Stack
- ASP.NET Core MVC
- .NET 8
- Entity Framework Core
- SQL Server / SQL Server Express
- ASP.NET Core Identity
- Bootstrap 5
- Chart.js

## Prerequisites
- .NET 8 SDK
- SQL Server Express instance running locally (or adjust the connection string to another SQL Server)
- VS Code or Visual Studio 2022

## Local Setup
1. Open a terminal in the project folder.
2. Install .NET dependencies:
   ```bash
   dotnet restore
   ```
3. Ensure the database connection string is correct in `appsettings.json`.
   - This project is configured for SQL Server Express by default:
   ```json
   "DefaultConnection": "Server=localhost\\SQLEXPRESS;Database=AcxiomCRMDb;Trusted_Connection=True;MultipleActiveResultSets=true;TrustServerCertificate=True;Encrypt=False"
   ```
4. Create and apply the database schema:
   ```bash
   dotnet tool install --global dotnet-ef
   dotnet ef migrations add InitialCreate
   dotnet ef database update
   ```
5. Start the app:
   ```bash
   dotnet run
   ```
6. Open the local URL shown in the terminal, usually:
   - http://localhost:5000
   - or the HTTPS URL generated by ASP.NET Core

- `Manager`
- `SalesExecutive`

- Password: `ChangeMe123!`

Important: change this password immediately in development and never use seeded credentials in production.

## Project Structure
- `Controllers/` - MVC controllers and API endpoints
- `Models/` - entity and view models
- `Views/` - Razor views
- `Data/` - EF Core DbContext and seed logic
- `Services/` - business services such as auditing
- `Migrations/` - EF Core migration files
- `wwwroot/` - static assets

## Notes
This is a functional assignment baseline, not a production-hardened deployment. Before using it in a real environment:
- review authorization and role scoping
- secure secrets and configuration
- use a hardened database setup and proper TLS/HTTPS settings
- replace development seed credentials
- validate login flow and permissions for each role

## Troubleshooting
If the app cannot connect to the database:
- confirm SQL Server Express is installed and running
- verify the server name matches your instance
- test connectivity with SQL Server tools
- ensure the database exists or run `dotnet ef database update`

If `dotnet` is not recognized, install the .NET 8 SDK and make sure it is added to your PATH.
